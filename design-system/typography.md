# Typography

## Purpose

This document provides reusable typography guidance for AI-assisted RWLV design workflows.

It does not define final font files, type sizes, weights, line heights, letter spacing, or implementation requirements unless confirmed by source documentation.

## Evidence Sources

Confirmed by brand doctrine:

- `design-system/brand.md`
- `design-system/tokens.md`

Confirmed by brand guidelines:

- `design-system/brand-guidelines/rwlv-brand-guidelines-2026.pdf` includes typography guidance, but exact reusable specifications were not extracted into this document.

Observed in pilot outputs:

- Conrad pilot required clear package benefit, proof, and booking hierarchy.
- Entertainment pilot required clear section identity, venue relationship explanation, and action clarity.

Unknown:

- Exact approved font names, type scale, weights, line heights, tracking, and breakpoint-specific typography rules.

## Typography Personality

RWLV typography should feel editorial, premium, readable, confident, and precise.

Use typography to:

- Create arrival when the content has earned it.
- Make complex hospitality information feel calm.
- Clarify relationships between experiences, venues, packages, offers, and actions.
- Support scanning without making the page feel generic or purely utilitarian.

## Display Usage

Use display typography sparingly.

Appropriate uses:

- Major arrival moments.
- Campaign or experience titles.
- Editorial openings.
- Premium quotes or proof moments when approved.

Avoid:

- Display-scale type in dense cards, compact panels, FAQs, filters, or booking controls.
- Multiple display treatments competing in one viewport.
- Oversized type used to compensate for weak hierarchy.

## Heading Usage

Headings should communicate structure and priority.

Guidance:

- Use clear heading levels that match the content hierarchy.
- Keep section headings specific to the guest need.
- Use subheadings to explain relationships, not to repeat marketing language.
- Preserve semantic order when inserting modules into existing pages.

Pilot-derived guidance:

- When taxonomy can be misunderstood, the heading should identify the primary experience or venue clearly.
- When proof validates benefits, headings should keep the benefit and evidence relationship easy to scan.

## Body Usage

Body copy should be readable, concise, and hospitable.

Guidance:

- Use body copy for explanation, context, and confidence-building.
- Keep paragraphs short enough for scanning.
- Prioritize practical clarity over decorative prose.
- Avoid burying constraints or eligibility in ornamental language.

## Label Usage

Labels should be precise and functional.

Use labels for:

- Category.
- Venue.
- Date or timing.
- Package inclusion.
- Offer eligibility.
- Action intent.
- Source or proof context.

Avoid:

- Vague labels such as premium, exclusive, or featured when they do not clarify the guest decision.
- Labels that create false hierarchy or imply unconfirmed relationships.

## CTA Copy Hierarchy

CTA copy should make intent clear.

Guidance:

- Use decisive language for primary actions.
- Use secondary actions for exploration, detail, or comparison.
- Avoid multiple primary CTAs in the same decision area.
- Keep CTA labels specific enough to distinguish booking, ticketing, reservation, package detail, and venue discovery.

Confirmed doctrine:

- Conversion should feel like hospitality, not pressure.

## Hierarchy Rules

Reusable rules:

- Arrival: largest and most expressive typography only when the content is a true entry point.
- Discovery: clear section headings with concise supporting copy.
- Evaluation: structured headings, labels, and body copy that support comparison.
- Decision: action labels and supporting copy should be direct and calm.
- Support: FAQ and terms typography should prioritize readability and scannability.

## Readability Guidance

Typography should remain legible and composed across content types.

Guidance:

- Avoid long all-caps passages.
- Avoid decorative type for operational details.
- Keep line lengths comfortable.
- Use contrast between heading, body, labels, and CTAs to support scanning.
- Let typography reduce cognitive load in dense modules.

## Mobile Readability

Mobile typography should support sequential focus.

Guidance:

- Keep headings compact enough to avoid awkward wraps.
- Use concise body copy.
- Keep CTA labels short and specific.
- Maintain enough spacing between headings, copy, controls, and cards.
- Avoid relying on side-by-side hierarchy that collapses poorly.

## Accessibility Considerations

Typography should support:

- Semantic heading order.
- Readable text size.
- Sufficient contrast.
- Clear link and button distinction.
- Legible text over imagery.
- Scannable FAQ and support content.

## Unknowns

Do not invent:

- Exact font names.
- Exact type sizes.
- Exact weights.
- Exact line heights.
- Exact letter spacing.
- Responsive type scale values.

Future agents should use confirmed brand or design-system sources before adding those details.
